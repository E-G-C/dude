## Selected-Task Read Enrichment

FR-018 permits this specific change to the former no-reader-change plan. Add a `taskDetails` member to the existing selected `readNowProjection` result carried by `/api/refresh`; do not add an endpoint or a general task API. Keep current `tasks` counts and `phases`, deriving rows and rollups from the same admitted source set. The small contract below belongs here; no separate schema or data-model artifact is needed.

| Information | Read-only projection rule |
| --- | --- |
| Coverage | Distinguish available task definitions, no package/not applicable, and unavailable task detail with a reason. An empty collection means a successfully read source contains zero canonical tasks, never a failed read or missing mapping. |
| Identity and rows | Bind the collection to the selected exact idea/spec pair and existing source identities. Each item carries its durable `taskKey`, title, recorded state, phase heading/order where available, and source reference; tracked items also retain their issue ID. |
| Instruction | Carry the complete available canonical unit as source text. Source coverage distinguishes a full file-backed unit from an imported description that does not expose the original body. Do not pass body text through `orientationText`, trim it to a headline, or line-clamp it. |
| Dependencies and blockers | Carry existing dependency keys and explicit blocker text with their source/availability. Readiness is separate from the four recorded states and may be unavailable. A missing dependency field is not proof of no dependencies. |
| Results | Current selected readers expose no structured task-bound verification/review outcomes. The inspector must say **Not exposed by this source**, not emit pass/review badges from glyphs or acceptance prose. Explicit records already present inside an exact unit/issue remain available as attributed source text; this addition does not interpret arbitrary prose as a verdict. |
| Freshness | Reuse the enclosing `readAt`, captured source identities, selected coverage, and freshness result. Do not introduce a task clock, revision store, or live-agent status. |

### File-backed definitions and Lightweight work

Use the already read selected `taskBytes` and `parseVisibleTasks` result. Reject parser warnings or invalid source structure under the existing unavailable path. Canonical membership, durable keys, states, dependencies, and blocker fields come from that parser, not a new Markdown regex parser.

For each admitted task, extract its raw unit from the original bytes using the visibility scan's byte-line offsets and the parser's `headerLine`. Bound it by the next canonical header, the next visible structural section boundary used by the existing phase treatment, a board boundary, or the terminal active-prefix end, whichever ends the unit first. Include intervening blank lines, indented prose, acceptance/context, and fenced examples as literal text. Use the masked scan to recognize boundaries, not as display text; otherwise source content disappears. Add only this bounded extraction to the selected projection. `extraMeta` is not a substitute: 062's body and acceptance paragraphs follow blank lines.

Reuse existing phase grouping and document order; keep valid unphased tasks under the existing Work fallback. Never sort phases or infer scheduling from the feature's lifecycle number. Generated board rows, terminal history/archive, and task-like syntax hidden by the canonical visibility scan are not tasks. A following `## Discovered During Execution` section must not enter the preceding task body; its tracked mirror is not a source for spec-derived task detail or a backfill for unavailable Beads data. If such non-authoritative material prevents establishing the required task set, report coverage rather than silently dropping rows while retaining their counts.

Use `readyTasks` and the parsed dependency states for **Ready by recorded task dependencies** versus **Waiting on dependencies** within Pending. Keep explicit `blockedBy` text separate, including when the recorded glyph and note disagree; do not silently normalize a glyph. A ready-by-dependencies label is not Work admission, design approval, or proof of an agent. A blocked glyph without an explicit reason remains blocked with reason coverage named.

The existing all-todo branch already reads and validates the task file, then omits its task counts/phases. Return planned rows, counts, and phases there too, while preserving `authority: definition`, stage Defined, and the absence of execution evidence. Do not manufacture Next or start work. Draft/no-owner handling still supplies no task definitions; missing or malformed owned task files remain unavailable.

When Next identifies a task, use that exact task's enriched unit for the full body in Now. Its existing short orientation text remains the heading/summary. A tracked title or Lightweight header alone must no longer be described as the full instruction.

### Tracked work

Keep global tracked precedence and the existing bounded complete-list acquisition. Select only non-epic issues with the exact `spec: <selected specPath>` first line. Within that set, require an unambiguous imported `Task:` durable key, using the existing carrier and shared task-key grammar, and a unique issue/key mapping. Do not search arbitrary description prose for the first key: dependency references are not task identity. Missing, conflicting, or duplicate mapping yields explicit task-detail unavailability, not a guessed key or `tasks.md` fallback. Independently established board totals may remain labeled as such, but an incomplete mapped list cannot claim to enumerate them.

Use `normalizeBeadsIssue` for recorded state and the existing list/readiness/blocker routines for facts. Return the entire available issue description and any directly supplied acceptance/context text as inert, attributed text. Do not add `bd show`, history queries, or per-row commands. Imported `Deps:` text is a recorded dependency declaration; it is not proof of current Beads readiness. Use the already correlated ready result when acquired. If the active-task branch did not acquire readiness, label it not exposed rather than querying per row or treating every other open issue as waiting.

The inspected import helper does not guarantee phase headings or the original multiline task body in its generated issue description. Show **Phase not exposed** and **Only imported description available** where appropriate. Do not reconstruct phases from task number, priority, or story, read the markdown mirror to fill gaps, or change import/storage contracts for this view. Core must not import an installed optional pack; the pack's source is a reference for the existing carrier, not a runtime dependency.

Task-level evidence remains deliberately limited. Feature Activity, ReviewHistory, and source test files cannot populate task result labels. Even 052's task-key-bound Work history is not exposed by the current selected reader; do not pull in recovery execution, parse its audit as a new observability feed, or mine logs for a latest success. The full unit/issue can display a literal task-bound result if that text is already present, but structured result coverage remains not exposed absent an existing reader-provided binding.

### Refresh, bounds, and safe rendering

Return descriptors only from the selected-feature path, never in `contexts`, `readWorkIndex.items`, or a second board/store. Reuse the same task-file or tracked-list captures for rows, counts, and phase totals. Include any consumed source in `completeProjection`/`verifySelectedSources`; preserve all-or-retained refresh, source checks, and data-hook epochs. `currentOrientation` agreement must guard task rows/detail as well as Next when the work index and selected source differ.

Reuse safe regular-file/path checks and existing acquisition limits, including the shared 5-second Beads deadline, 8 MiB command buffers, and work-index package budgets. The selected file reader is not currently a separate byte-capped task service; do not claim it is or build one. This change adds no eager unselected reads or body truncation to meet a fabricated limit. Existing unavailable/overflow behavior remains explicit, and limits are not raised.

Render unit/issue text through React text children with wrapping and preserved line breaks in the readable body style. Do not inject it as HTML, run scripts, render active source markup, or add a new rich-text dependency. Local row selection, disclosure, and filtering need no network action.

## Chosen Composition

Keep `App` as the composition owner, using existing view, finder, selection, input, and Review lifetimes. The VS Code/Fluent list-and-inspector convention makes individual tasks inspectable without adding another work selector.

1. **Shared chrome and one finder.** In every view, committed selection determines whether the main selector shows the sole `WorkFinder` search/Show controls or Working on with subordinate Clear. Selected Overview shows only that exact row with truthful copy/counts and can reopen its Now. Keep initial Overview/Open. Explicit Clear empties query, uses All, resets lookup scroll/roving position, and focuses the same Overview search. Ordinary navigation retains selection and applicable lookup state. Add no Switch work, second picker, lock, or confirmation.
2. **Numbered work rows.** Derive the display number from validated `context.ideaPath`, solely for zero-padded labels and numeric capture sorting. `ideaPath`/`specPath` remain the binding; keep number/name/status/progress in compact rows and accessible names. No new numbering API or inventory is needed.
3. **Now, Tasks, and the dock.** Keep the prominent object header and focal Next, then central lifecycle/progress, Tasks with existing phase headings/counts, and separate Activity. Default Tasks to All; its status filter changes only visible task rows, never the global finder or Next. A row uses the canonical title, phase association, and recorded state. In-progress indication and inspection selection have distinct text/visual semantics. One activation opens the task's full source, dependencies/blocker, and result-coverage explanation in the existing dock above feature-property disclosures. At narrow widths, render the same inspector in flow after that row. Keep the full body readable and all task controls read-only.
4. **Local inspection and return.** Keep only a tab-local task key and status filter under the existing selected feature, not a second feature value or persistent per-feature store. Bind resolution to root identity, exact idea/spec pair, and the current agreeing projection. Clear or feature change discards both before rendering new context. Ordinary return can retain them for the same feature/key; a removed key or a filter that hides it dismisses detail. Return focus to the row, or keep it on the filter when filtering caused dismissal. Source changes refresh the body from the new agreed read, never from a separately retained task object.
5. **Requests.** Reuse current feeds and exact scope comparisons: one current matching request may open directly; several require choice. Needs You keeps session and other-feature requests independently of work/task filters. Show Browsing when the open request differs from the selected feature and name its actual scope on the request surface. New idea does not inherit selection. No task click changes a request, form, approval, or send handler.
6. **Focused Review.** Retain `previewEligibility`, `openReview`, `requestKey`, `reviewReturn`, saved markup, caret/focus, cancellation, and revision invalidation. Keep the engine mounted and the reviewed frame pinned. Task/property disclosure cannot reflow the frame or retarget its source; Review remains a user-entered child, not a rail destination.
7. **Responsive/status treatment.** Use available width, bounded prose, and identity/Next before secondary detail. At 360px the compact bar may ellipsize; the main number/name must wrap. Keep work/request coverage, last complete read, source freshness, and connection state distinct. An in-progress row gets no live-agent animation or claim.

Keep the rail contract unchanged: `TABS` remains `overview`, `context`, `needs`, `new`. The dedicated menu toggle is distinct from Overview's grid icon and announces `aria-expanded`/`aria-controls`; destinations retain accessible names and `aria-current`. At >=720px, default to 48px compact and expand inline to 208px nonmodally; below 720px, use the compact row and 260px labeled overlay. Only that overlay makes all covered background, including prototype chrome, inert and contains Tab/Shift+Tab. Escape, Close, dimmer, destination selection, and width transitions use the same dismissal/focus-restoration path. Preserve inputs and pinned Review geometry. No Settings/Packs destination, cog, or persisted preference is added.
