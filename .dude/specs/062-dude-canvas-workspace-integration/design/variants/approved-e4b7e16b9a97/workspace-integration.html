Discovery and Now always read this repository's frozen records, and the frozen 062 record is Defined with all five canonical tasks not started. Its task rows, phase totals and unit text were captured from tasks.md with the product's own parser. Every selection except Repository facts only replaces that record's execution state — stage, next step, or a named task's recorded state — with a controlled example, recomputes the counts beside it from that same example, and supplies the example request feed, exactly as the product would receive them from a live session.

It is one search, on screen only while no record is committed: once work is committed the record keeps the chrome in every view and Clear on that record returns to the same search.

    Adapted

    • Committed work leads the chromeChanged for the 2026-09-14 command-bar review. The chosen record now sits first in the command bar with a brand edge, its number in the brand ramp and its full title at body size; Clear is demoted to quiet text. 052 carried one context control, and the reviewed revision put a wide search field in front of a small Selected chip.
    • One work search, never twoChanged for the same review, then simplified when the added Switch work control was rejected as redundant, and changed again for the 2026-09-14 review that asked for a single main search: to switch work you clear the filters first. The committed record, not the current view, now decides what the one selector shows. While work is selected the search and Show selection are gone everywhere — Overview included — and Overview lists only that selected record, with counts and wording that say so instead of "Nothing is selected"; that row reopens the same Now. Clear is the one way back: it ends the selection, empties the search, shows All records, returns the list to the start and puts the caret in that same field, so an earlier query cannot trap the next choice. The empty search, All records and starting position are the definition owner's reading of "clear the filters", not a literal answer from the review. Clear ends the work filter only: no work is closed or cancelled, no request answered, no draft or saved local markup lost. Launch still opens Overview on Open, and ordinary navigation while nothing is committed keeps the search, Show selection and list position.
    • Selected record as the object headerChanged for the same review. Number and name now lead Now at 24px with the record's state beside them and its Review design action attached, instead of a 16px line under a breadcrumb that repeated the same title. The breadcrumb keeps the number only.
    • Rich numbered rowsEach row carries the zero-padded lifecycle number with name, status and progress, in ascending capture order. 052 listed one identifier per row; 057 sorted alphabetically.
    • Tasks, with the phase summaries inside itAdded for the 2026-09-14 review that accepted a read-only task drill-down. 052 and the earlier revisions of this mock showed phase rows and counts with no way to see the individual tasks, so counts and one Next instruction were all the detail available. The old Phases region is now the top line of each group in Tasks — same headings, same file order, same unfiltered totals — with the canonical rows under it and a section-local All / Pending / In progress / Blocked / Done filter that changes only which rows are drawn. It never touches the one work search, the Show selection, the committed record, Next or a request. Phase totals stay unfiltered and the matching-row count is stated separately; an empty filter says the filter is empty, not that the package has no tasks.
    • A read-only task inspectorOne activation on a row opens the whole recorded unit — body paragraphs after blank lines, acceptance and context text, quoted examples — as wrapping body text in the existing dock above the record's own properties, and in the work column under its row once the dock folds in at 1080px. Source text is rendered as text and never runs. Dependencies are listed with each one's recorded state, an explicit blocker stays separate from waiting on a dependency, and task-bound verification or review results read Not exposed by this source because the current readers expose none. There is no checkbox, Run, Retry, Stop, Mark done or Edit: the row selects what to read and nothing else. This detail is local to the tab and to that exact record — Clear or a different record drops it and the filter before the next context is drawn, and a filter that hides the row being read closes it and keeps focus on the filter.
    • Next as body textThe full recorded instruction is readable body text under a short "Next step" heading, instead of 052's oversized headline.
    • Real rail destinationsOverview, Now, Needs you and New idea all work. 052's five disabled "later cycle" buttons are gone. Overview now carries a grid glyph instead of the three-line one, so the only menu-shaped control on the rail is the menu.
    • Expandable labelled paneChanged for the 2026-09-14 rail review, which asked for the labels Fluent normally shows. A named hamburger above the destinations — "Expand navigation pane" / "Collapse navigation pane", with aria-expanded and aria-controls on the destination list — switches the same four destinations between compact icons and icons with labels at 208px. Compact stays the default, so the established layout is what opens. The toggle is disclosure only: it never navigates, never touches the committed record, the search, the Show selection or the list position, sends nothing, and never redraws the work area, so unsent input, the caret and an open Review's pinned stage and pan survive it. The choice lives in the tab, not in a stored preference.
    • Narrow navigation and returnUnder 720px the four destinations stay as one compact row and the same toggle opens them as a labelled overlay menu over the work area instead of squeezing it — the named control, Escape or the dimmer closes it and focus returns to that control. The dock becomes an in-flow disclosure, and an ordinary return keeps the selection, and the search, Show selection and position of an uncommitted finder.
    • Focused ReviewReview is a child view entered from a current request, with secondary detail disclosed under a stage that pans inside itself.
    • Prototype strip held away from the productChanged for the 2026-09-14 command-bar review, which asked whether the explanation band was part of the product. The strip is now hatched, flagged and closed by a labelled edge; nothing it explains has been hidden.

    Deferred or omitted

    • Inert future navigationWork, Artifacts, Memory and Team rail buttons are not drawn, because nothing stands behind them.
    • Dude settings at the foot of the paneThe same review raised a settings cog for packs and the rest, where Fluent and Office put it: bottom-left, under the destinations. It is not drawn here, in any state. 062 has no settings or packs surface to open and excludes that management, so a cog — even a quiet one — would be a control that leads nowhere. Where it would sit is recorded; whether it is built is a separate intake decision, and this mock does not presume it.
    • Automatic Review opening (054)Review still requires a deliberate action on a current request.
    • Annotation direct manipulation (059)The existing annotation grammar is shown unchanged; no new manipulation is proposed.
    • Editing artifacts, arbitrary commands, execution controlsOut of scope for 062 and absent here.
    • Omission is not cancellation: the broader 052 direction remains the product direction.

    Walkthrough this mock supports

    • DiscoverSearch or scope in the command bar; every matching record is reachable by scroll and keyboard.
    • SelectOne activation on a row opens that exact record in Now, where its number and name lead the work area; nothing is selected for you.
    • SwitchSwitching work starts by clearing its filter. Overview keeps the record you are on and lists only that record until you clear, and Clear on the committed record is the single way back to the search: it ends the selection, empties the search, shows All records, returns the list to the start and focuses that same field. Neither closes, cancels or discards anything.
    • ReorientNext step or the reason there is none, lifecycle, progress, the phase-grouped task rows, activity, and evidence in the dock.
    • Inspect a taskChoose a row in Tasks, by pointer or keyboard, to read its whole recorded unit, its dependencies, any explicit blocker and what the source does not expose. Filter the rows by recorded status without leaving the record. Everything here is read-only.
    • Answer or reviewOpen a current request from Now or Needs you, answer it, or enter Review for an eligible preview. Requests for other scopes stay listed and keep their own scope while work is selected.
    • ReturnBack returns to where you came from with the selection, unsent input and Review work intact; an uncommitted finder also keeps its search, Show selection and list position. Only Clear resets the work lookup.
