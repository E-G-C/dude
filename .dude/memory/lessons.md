Solved challenges, learned patterns, and candidate future skills.

## Entries

- Early lightweight/tracked lessons, now enforced by shipped contracts and kept only as rationale: require an explicit `.dude/specs/<feature>/` path and never guess when several feature directories exist (now the canonical exact-owner resolver); stop import on malformed or ambiguous `tasks.md` lines instead of inferring intent (now `parseTasks` plus the import contract); never keep `tasks.md` as the live board after Beads import, where it is only a one-way mirror (now a bundle guardrail); and keep optional operational tooling explicitly opt-in to avoid workflow drift (now a bundle guardrail and decision).
- Re-define reconciliation needs access to pre-change lightweight task history, such as a preserved snapshot or VCS diff; the rewritten package alone is not enough to explain surviving versus ambiguous checked work reliably.
- When `@dude flag` identifies standalone work with no active task to mark `[!]`, persist it in a durable artifact before calling it flagged: Beads issue, new brief/spec package, or concise `.dude/memory/` context/lesson entry.
- Full test discovery: bare `node --test` under-discovers this repo's suite (it finds only top-level tests). Run the whole suite with `find . -path ./dist -prune -o -name '*.test.mjs' -print0 | xargs -0 node --test`.
- Bundle-change validation gate before committing: require the full suite green, workspace lint at 0 warnings / 0 failures, `compose verify` exit 0, and `git diff --check` clean. Build and lint a pristine release with 0 failures; for the current release shape, accept only the known `FEATURE_IDEAS_ROOT_MISSING` warning because releases omit project ideas. A different warning is not baseline; compare suspected regressions against a clean detached baseline worktree. After `build-dev`, inspect `git status --porcelain -- .github` for intended net changes. Its `N removed` value counts generated core paths deleted during cleanup and then regenerated; it is neither fixed nor evidence of net tracked deletion.
- Never inspect a built release/output directory after running `compose add` against it — the install writes pack files and a `profile.md` into that dir and can yield false-positive "broken state" findings. Build to a pristine directory for release inspection.
- Before technical-docs extraction, separate the user's immediate document deliverable from optional multi-mode acceptance, run deterministic intake first, and report files, units, expected model calls/batches, and ETA. Require explicit approval above 20 units/calls or 10 minutes; use a focused subtree or representative fixture for repository mode rather than a whole medium repository. Reuse verified prior evidence for pipeline-generated document updates when possible, and never double model calls merely to finalize deterministic fragment metadata.
- Work host adapters must preserve run state and distinguish refusal from process failure. Emit `stateBase64` plus `stateHash` in tool output and checkpoint outside the worker; a shell variable or process memory alone loses the run and its diagnosis when a wrapper throws and exits. Feature 018 fixed this retention. A closed refusal with unchanged state is a normal outcome to inspect and route on; never exit, retry blindly, or tear down the run merely because a routed call refused.
- Verify review findings by reproduction before acting on them. In Feature 018 every claim backed by a running reproduction was real, while several confident static-only claims were already handled and would have caused needless rewrites. Mutation testing is the only reliable proof a guard is pinned: delete the clause, confirm the owning test fails with its own message.
- An unreachable guard cannot be honestly covered. When a typed refusal is dominated by an earlier check on the same bound, delete it rather than lowering a ceiling or reordering to make it fire, since a fixture built that way certifies a branch that cannot execute in production. Record the dominating invariant in one comment at the site it protects.
- A specialist without terminal tools that refuses to hand-copy files or invent profile state is behaving correctly. Take the refusal as a real finding and complete the step where the authoritative parser and serializer are available, instead of pressing the specialist to guess.
- Static content-presence tests cannot see templated prose. Feature 020's cross-file repetition report found a clause repeated verbatim in five files and a phrase in six across the Feature 017 docs while every contract test stayed green, and plain `grep` missed both because the docs are hard-wrapped and case-varied. Run `node .github/skills/dude-pack-writing-avoid-ai-tropes/repetition.mjs <files>` on any multi-document set before calling its prose done.
- First definition is a transaction, not a byte copy. Stage exactly `current-idea.md`, `staged-idea.md`, `spec.md`, `plan.md`, and `tasks.md` in one coordinator-owned OS temporary directory, then invoke `publish-first-definition.mjs` as prescribed by `dude-feature-definition`. The helper atomically applies the owner transition and core trio with lint inside the rollback boundary. It preserves title and slug bytes, complete protected-section bytes, and the prior Coordinator Log prefix with exactly one appended event. Its real-CLI tests cover successful publication, preflight refusal, and lint rollback.
- Untrusted-boundary attribution: when an untrusted or caller-supplied value could become a field the system is contracted to own (a reason/status code, identity, or attribution), restrict it to a closed owned allow-list with a safe default — never pass it through or try to sanitize arbitrary input. Feature 022: an untrusted host `exchange` error's arbitrary `error.code` was leaking in as the runner's own terminal halt reason; the fix was a frozen runner-owned reason-code set defaulting to `exchange-context-lost`.
- Never hand-roll task-state or glyph counts from raw `tasks.md`. Use `parseTasks` from `dude-engine/lib/tasks.mjs`, the grammar’s single source of truth: it excludes the generated `dude:board` fence and terminal `## Lightweight Execution History` archive while preserving valid unphased tasks and tasks under arbitrary `##`/`###` headings.
- Prose contracts should pin each required behavior with a section-bound presence check and a labeled deletion falsifier. Do not use broad paraphrase regexes to decide semantic contradiction in free prose: Feature 034's three unbounded patterns missed simple paraphrases, and one rejected required current-repository wording. Closed checks for a fixed set of named prohibited capabilities remain useful; independent review owns residual semantic conflict. Probe by deleting the whole owning block and each rule separately. In Feature 034, one eight-line block and several individual rules could be removed while focused tests stayed green. Match whitespace-normalized paragraphs so a pure Markdown rewrap does not fail.
- Monotonic `.dude/specs/` numbering has no cross-branch lock: this branch and `main` independently minted `033`. Before defining on a long-lived branch, run `git fetch origin main`, then inspect `git log --name-status HEAD..FETCH_HEAD -- .dude/specs/` for incoming prefixes; this reduces collision risk but is not a lock. Resolve a collision by renumbering the later-merged package with `git mv`, updating the owner idea's `spec_path:` and every exact package reference, and refreshing affected derived projections through their owning tools. Append one renumber event while preserving earlier Coordinator Log entries.
- Shipped core agent, skill, instruction, and user-facing prose must be self-contained: never rely on a feature-local `FR-###` or `SC-###` identifier for runtime guidance, because release bundles omit project specs. Translate the requirement into concrete behavior; keep those identifiers only in definition and test traceability where they remain resolvable.
- Copilot CLI 1.0.83-5 lifecycle lesson from Feature 057 T007: isolated real-CLI probes showed that root abort did not abort the pending invocation signal, which also aborts after ordinary completion. Correlate documented root abort and pending_messages.modified events with a current bounded waiter; queue presence is not an accepted answer. A typed unresolved outside_input_available result through normal transport preserved outside messages, whereas SDK resultType:"rejected" discarded queued input. Reverify other SDK/host versions. Evidence and scope limits are linked from .dude/ideas/057-dude-canvas-needs-you.md#coordinator-log.
- Headless Edge 133.0.3065.69 on macOS can answer CDP while native motion stops because its document becomes occluded/hidden. In Feature 057 T008, finite 200ms animations and the document timeline stayed at zero; Page.bringToFront did not help. Adding only --disable-backgrounding-occluded-windows to the test-owned launch restored native progress and unchanged readiness checks. Inspect visibility/timeline evidence before changing UI, bound command and phase waits, and distinguish infrastructure BLOCKED from application FAIL. Reverify other browsers/hosts; this is a scoped test-launch correction, not a runtime prerequisite. Evidence: .dude/ideas/057-dude-canvas-needs-you.md#coordinator-log.
- CDP rawKeyDown is silently dropped after Tab focus wraps past the end of the document in headless Edge on macOS; use keyDown for navigation keys in browser tests. Reproduced with no product code involved: a Tab walk that never wraps lost 0 of 130 keys, while one wrap past the end lost 110 of 110, and two wraps lost 0 of 10. Delays of 50, 250 and 1000ms did not help, and removing the sandboxed iframe did not help, so it is browser-side input suppression rather than anything about the page. Only keyDown clears it, 8 of 8 delivered against 0 of 8 for rawKeyDown. This produced a test that looked like a load-dependent flake for days because whether tabTo wrapped depended on popover render timing, so an odd number of wraps swallowed the key and an even number did not; that parity matched the pass/fail outcome 16 times out of 16. Rejected with evidence rather than assumption: Emulation.setFocusEmulationEnabled, renderer-side focus and blur-then-focus calls, and Page.bringToFront, which fixed an isolated oracle but made the real test worse and added a second failure mode. The wider lesson is that a test failing intermittently in a full suite and passing in isolation is a hypothesis, not a diagnosis; this one changed character to near-deterministic and a bisect then exonerated the suspected production change, because reverting it made the failure more frequent rather than less.
