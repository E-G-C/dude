# Dude Lessons

Solved challenges, learned patterns, and candidate future skills.

## Entries

- Early lightweight/tracked lessons, now enforced by shipped contracts and kept only as rationale: require an explicit `.dude/specs/<feature>/` path and never guess when several feature directories exist (now the canonical exact-owner resolver); stop import on malformed or ambiguous `tasks.md` lines instead of inferring intent (now `parseTasks` plus the import contract); never keep `tasks.md` as the live board after Beads import, where it is only a one-way mirror (now a bundle guardrail); and keep optional operational tooling explicitly opt-in to avoid workflow drift (now a bundle guardrail and decision).
- Re-define reconciliation needs access to pre-change lightweight task history, such as a preserved snapshot or VCS diff; the rewritten package alone is not enough to explain surviving versus ambiguous checked work reliably.
- When `@dude flag` identifies standalone work with no active task to mark `[!]`, persist it in a durable artifact before calling it flagged: Beads issue, new brief/spec package, or concise `.dude/memory/` context/lesson entry.
- Full test discovery: bare `node --test` under-discovers this repo's suite (it finds only top-level tests). Run the whole suite with `find . -path ./dist -prune -o -name '*.test.mjs' -print0 | xargs -0 node --test`.
- Bundle-change validation gate before committing: full test suite green; `node .github/skills/dude-lint/lint.mjs .` 0 warnings / 0 failures; `node .github/skills/dude-compose/compose.mjs verify` exit 0; `build-release` then lint the `dist` output 0 failures — its baseline is 1 warning, `FEATURE_IDEAS_ROOT_MISSING`, because releases ship no project ideas, so treat 1 warning / 0 failures as clean and confirm any suspected regression by building the same release from a detached `HEAD` worktree; after `build-dev`, `git status --porcelain -- .github` shows only the intended files (its constant "N removed" count is a fixed cleanup list, not deletion — verify with `git status`, which shows none); `git diff --check` clean.
- Never inspect a built release/output directory after running `compose add` against it — the install writes pack files and a `profile.md` into that dir and can yield false-positive "broken state" findings. Build to a pristine directory for release inspection.
- Before technical-docs extraction, separate the user's immediate document deliverable from optional multi-mode acceptance, run deterministic intake first, and report files, units, expected model calls/batches, and ETA. Require explicit approval above 20 units/calls or 10 minutes; use a focused subtree or representative fixture for repository mode rather than a whole medium repository. Reuse verified prior evidence for pipeline-generated document updates when possible, and never double model calls merely to finalize deterministic fragment metadata.
- Never hold autonomous run state solely in a shell environment variable or one process's memory. A wrapper that throws and runs `exit` destroys the only copy and ends the run irrecoverably with no diagnosis. Emit the state as `stateBase64` plus `stateHash` in tool output so it survives shell death, and checkpoint it outside the worker. Feature 018 fixed this in the Work host adapter.
- A closed refusal that returns unchanged state is data, not a process failure. Treat it as a normal outcome to inspect and route on; never let a wrapper exit, retry blindly, or tear down the run because a routed call refused.
- Verify review findings by reproduction before acting on them. In Feature 018 every claim backed by a running reproduction was real, while several confident static-only claims were already handled and would have caused needless rewrites. Mutation testing is the only reliable proof a guard is pinned: delete the clause, confirm the owning test fails with its own message.
- An unreachable guard cannot be honestly covered. When a typed refusal is dominated by an earlier check on the same bound, delete it rather than lowering a ceiling or reordering to make it fire, since a fixture built that way certifies a branch that cannot execute in production. Record the dominating invariant in one comment at the site it protects.
- `compose` has no refresh path for an installed pack whose source changed in-repo: `remove` refuses because the persisted inventory no longer hash-matches the source, `add` no-ops with `alreadyInstalled` even under `--force`, and `remove` accepts no `--force`. To resync, restore the recorded source (the installed `.github/` projection still holds those exact bytes, and tracked edits can go to a scoped `git stash`), run `remove`, restore the new source, then run `add`. Extra untracked files in the source directory also break the hash, so move them aside too. Every in-repo pack edit needs this dance until a refresh path exists.
- A specialist without terminal tools that refuses to hand-copy files rather than fabricate profile hashes is behaving correctly. Take the refusal as a real finding and complete the step where the capability exists, instead of pressing the specialist to guess.
- Static content-presence tests cannot see templated prose. Feature 020's cross-file repetition report found a clause repeated verbatim in five files and a phrase in six across the Feature 017 docs while every contract test stayed green, and plain `grep` missed both because the docs are hard-wrapped and case-varied. Run `node .github/skills/dude-pack-writing-avoid-ai-tropes/repetition.mjs <files>` on any multi-document set before calling its prose done.
- First definition is a transaction, not a byte copy: the Spec Lead cannot create a missing package parent, and raw chat/`awk` extraction (used for Features 021-022) is not a supported byte transport. The deterministic helper has shipped and is the current route — stage exactly `current-idea.md`, `staged-idea.md`, `spec.md`, `plan.md`, `tasks.md` in one coordinator-owned OS temp directory, then run `node .github/skills/dude-feature-definition/publish-first-definition.mjs --root . --idea <idea> --spec <spec> --stage <abs-dir>`, which applies the owner transition plus core trio through `applyAtomicFileBatch` with rollback-bound lint. It enforces byte-identical `## Idea`, `## Open Questions`, `## Assumptions`, preserved `title:`/`slug:`, and exactly one appended Coordinator Log event, so stage those precisely. Verified end to end on Feature 034.
- Untrusted-boundary attribution: when an untrusted or caller-supplied value could become a field the system is contracted to own (a reason/status code, identity, or attribution), restrict it to a closed owned allow-list with a safe default — never pass it through or try to sanitize arbitrary input. Feature 022: an untrusted host `exchange` error's arbitrary `error.code` was leaking in as the runner's own terminal halt reason; the fix was a frozen runner-owned reason-code set defaulting to `exchange-context-lost`.
- Never hand-roll task-state or glyph counts from raw `tasks.md`. Use `parseTasks` from `dude-engine/lib/tasks.mjs`, the grammar’s single source of truth: it excludes the generated `dude:board` fence and terminal `## Lightweight Execution History` archive while preserving valid unphased tasks and tasks under arbitrary `##`/`###` headings.
- Prose contract tests must pin required text by presence, never by detecting contradictions. Feature 034's paraphrase-tolerant contradiction regexes both missed trivial paraphrases such as `Give the latest comment priority.` and flagged the spec-required sentence `Resolve a bare issue number in the current repository.` as a violation; a guard that rejects required behavior is worse than no guard, so semantic contradiction added alongside a retained denial belongs to independent review, which caught it every time. Two further traps: deleting an entire documented rule block left the focused suite green twice, so probe by deleting the whole block and each rule alone and require each to emit its own labeled failure, because joint satisfaction hides gaps; and `assertSectionRuleRejectsMutations` needs a globally unique exact physical line, so in hard-wrapped Markdown a rule spans lines and a pure rewrap with identical words turns the suite red — match whitespace-normalized paragraphs instead.
- Monotonic `.dude/specs/` numbering has no cross-branch guard: a feature branch and `main` independently minted `033` and collided at merge. Renumber the later-merged package rather than reusing the prefix — `git mv` the directory, update the idea `spec_path:`, in-package references and the `.dude/state/task-state.json` key, then regenerate `.github/` with `build-dev` and both backlog projections instead of hand-merging generated conflicts — and append one Coordinator Log event recording the renumber while leaving earlier append-only entries naming the old number untouched. Check `git log HEAD..origin/main` for a colliding prefix before defining a package on a long-lived branch.
