# Dude Lessons

Solved challenges, learned patterns, and candidate future skills.

## Entries

- Use the exact-owner resolver and `parseTasks` instead of guessing feature identity or counting task glyphs with text searches. The parser excludes generated boards and terminal history while retaining valid unphased tasks. Malformed or ambiguous input stops import; after Beads import, markdown is only a mirror. These are existing contracts, as is keeping optional tooling opt-in.
- Definition publication and reconciliation need preimages. First definition uses the five-file stage and `publish-first-definition.mjs` prescribed by `dude-feature-definition`, with lint inside rollback. Re-definition must retain prior task identities, states, and append-only history; a rewritten package alone cannot prove which completed work survived. Do not replace the owning transaction with hand-copied bytes.
- Lifecycle numbering has no cross-branch lock: this branch and `main` both allocated `033`. Fetch and inspect incoming idea/package identities before first capture or definition on a long-lived branch; the canonical publisher still owns local allocation. A collision needs explicit owning-workflow reconciliation of paths, references, and derived views with prior history preserved. Numbering never supplies execution order.
- A standalone flag with no active task must be retained before calling it recorded. Use an authorized memory entry or the explicit brainstorm route for requested future work; do not manufacture a blocker on completed work or create a definition package merely because the user said `flag`.
- Test discovery must prune `node_modules`, `dist`, and `.git`; bare `node --test` under-discovers this repository. Use the commands in `docs/commands.md#canvas-maintainer-acceptance`, running the two heavy browser suites explicitly and serially with required-browser mode. Keep executed, failed, and skipped counts visible in evidence; a passing wrapper or skipped suite is not coverage.
- Validate the exact deliverable, including staged Git bytes and source/generated/static/legal parity. Require applicable suites, lint, composition, and whitespace checks; investigate every new warning rather than treating it as baseline. Preserve explicitly reviewed immutable-history formatting exceptions without calling a failed whitespace check clean. Inspect a pristine release before installing packs into it. Build-dev's removal count is cleanup activity, not net Git deletion. Keep implemented, committed, pushed, and merged claims distinct, and never infer Git permission from feature completion.
- Test the boundary the claim depends on. Feature 057's same-Chromium tests did not prove desktop-host capture; SDK types did not prove installed owner-tool execution. Cross-renderer computed styles are not pixel-equivalence proof: retain the declared portable checks and each renderer's local stability, and disclose unverified painting. Do not enlarge a short human observation into approval or unperformed steps. A specialist lacking terminal tools must hand execution to its owner, not invent evidence.
- Diagnose intermittent failures before labeling them flaky or environmental. Use controlled variants, actual input delivery, source/runtime identities, and observable settling conditions; a pass in isolation or a failed rollback alone does not identify the cause. Quiesce fixture mutation sources rather than retrying until green. Separate a reproduced mechanism from attribution of a particular historical user incident. The reusable procedure belongs in `dude-systematic-debugging`.
- A negative test must fail for its intended reason. Reproduce review findings and, where needed, remove the specific guard while keeping other evidence consistent; Feature 057 exposed an instability test that passed without its guard because its report hash also disagreed. Do not claim unreachable guards are covered or lower a resource ceiling to reach them; remove dead checks only after establishing the dominating invariant. Use `dude-verification-before-completion` for the general rule.
- Prose contracts need section-bounded checks, whitespace-normalized comparisons, and meaningful deletion falsifiers; broad paraphrase regexes cannot judge semantic conflict. Inspect multi-file repetition with the installed writing skill, including generated prose that static presence checks miss. Shipped guidance must state concrete behavior rather than depend on project-local requirement IDs that release bundles omit.
- Preflight structured handoffs with the receiver's available validators, complete authorized file scope, and evidence-capacity limits before submitting. Group overlapping checks only through their actual owner while preserving every obligation; never truncate results, hide changed files, or silently broaden permission. The 18-versus-16 handoff and later inventory-plus-evidence exhaustion are distinct incidents recorded in ideas 060 and 061; this prevention guidance does not implement either runtime fix.
- Preserve accepted Work state outside a replaceable worker and emit its bytes/hash through the supported adapter. Qualified unchanged-state refusals are data for the existing correction path, not permission for blind retries or process exit; hard stops keep their current rules. Closed owner-controlled reason codes must not accept arbitrary untrusted error strings; Feature 022 used `exchange-context-lost` for unrecognized exchange errors. Checkpoint bytes and equal states alone never grant identity, takeover, or cleanup authority.
- Read the reference implementation before expanding an adaptation. In Feature 057, Sharpie already rendered fresh pixels and composited markers; the added cross-engine equality machinery created an unsupported guarantee. Identify the actual upstream call path, reuse the bounded code and notices, and add only requirements with current callers and testable outcomes. Familiar UX patterns inform the design but do not replace approval.
- Evaluate the accepted user journey as well as task counts. Feature 057 supported new-idea capture without an existing-draft editor; name such exclusions early instead of inferring full CRUD or treating every later correction as new scope. Idea 058 retains the broader intake follow-up. This lesson grants no scope expansion or implementation authority.
- Copilot CLI 1.0.83-5 probes showed that root abort and the pending invocation signal differ, and the latter also aborts after ordinary completion. Correlate documented root-abort and `pending_messages.modified` events with the current waiter. A typed `outside_input_available` result preserved queued input where SDK `resultType: "rejected"` discarded it. Queue presence is not acceptance; reverify on other SDK/host versions. Evidence: Feature 057's Coordinator Log.
- Two separate Edge 133/macOS test issues are recorded in Feature 057's log. Occlusion stopped native animations while CDP remained responsive; the test-owned `--disable-backgrounding-occluded-windows` flag restored progress without weakening readiness. Separately, `rawKeyDown` was dropped after odd Tab wrapping; `keyDown` delivered the navigation event in a no-product reproduction. Delays and focus workarounds were not substitutes for diagnosis. Reverify other environments; neither finding is a consumer runtime prerequisite.
- For technical-docs extraction, separate the immediate deliverable from optional acceptance modes and estimate files, units, model calls, and time first. Preserve the existing approval threshold above 20 units/calls or 10 minutes for that workflow; prefer a bounded subtree or representative fixture. Reuse verified evidence for deterministic metadata updates instead of repeating model calls.
- Synthesize reusable prevention from the relevant implementation, failed approaches, review corrections, and delivery evidence; do not equate a positive feature-scoped retrospective with an exhaustive session review. Use `dude-learning-promotion` to separate solved lessons, existing guidance, proposals, and unresolved defects, then retain through the existing owner. Consolidation is not an automatic close hook, new review gate, or permission to rerun the one-shot retrospective.
