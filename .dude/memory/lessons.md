Solved challenges, learned patterns, and candidate future skills.

## Entries

- Use exact-owner resolution and `parseTasks`: include unphased tasks, exclude generated/archive rows, and reject malformed or ambiguous imports. After Beads import, markdown is only a mirror. Optional tooling stays opt-in.
- Follow `dude-feature-definition`: five-file stage, `publish-first-definition.mjs`, preimages, and rollback-bound lint. Re-definition preserves task identities, states, and append-only history. Never replace the transaction with hand-copied files.
- Lifecycle allocation has no cross-branch lock (collision: `033`). Fetch and inspect incoming identities before capture/definition on long-lived branches. Keep canonical allocation; reconcile paths, references, and views through the owning workflow, preserving history. Numbers never determine execution order.
- Persist standalone flags through authorized memory or explicit brainstorm before calling them recorded. A flag alone authorizes neither a definition package nor a blocker on completed work.
- Follow `docs/commands.md#canvas-maintainer-acceptance`: run both browser suites explicitly, serially, in required-browser mode. Prune `node_modules`, `dist`, and `.git` during discovery; bare `node --test` misses tests. Report executed/failed/skipped counts; wrapper passes and skips are not coverage.
- Verify staged bytes, source/generated/static/legal parity, and applicable tests, lint, composition, and whitespace. Investigate new warnings; preserve reviewed history-formatting exceptions without calling failures clean. Inspect pristine releases before adding packs. Build-dev removal counts are cleanup, not net deletions. Distinguish implemented/committed/pushed/merged; completion grants no Git permission.
- Verify the actual host, receiver, and renderer; same-engine tests, SDK types, and computed styles do not prove production or pixel equivalence (Feature 057). Preserve portable/stability checks and disclose limits. Never inflate human observations into approval. Specialists without terminal tools delegate execution.
- Follow `dude-systematic-debugging`: isolate runtime, source, input delivery, and settling conditions before labeling failures flaky/environmental. Quiesce fixture mutations instead of retrying to green. An isolated pass or reproduced mechanism does not establish a historical incident's cause.
- Negative tests must fail for the intended reason: remove the target guard while keeping other evidence valid (Feature 057). Never weaken invariants to reach unreachable code; remove dead checks only after proving the dominating invariant. See `dude-verification-before-completion`.
- Check prose contracts by section, normalize whitespace, and use deletion falsifiers. Regex cannot judge semantic conflict. Use the writing skill to check cross-file repetition, including generated prose. Shipped rules must explain behavior without project-local requirement IDs.
- Preflight handoffs against receiver validators, authorized file scope, and capacity. Group checks only through their owner; omit no obligation or evidence and never widen permission. Ideas 060/061 track distinct capacity failures; guidance does not fix them.
- Preserve accepted Work state outside replaceable workers; emit bytes/hash through the supported adapter. Qualified unchanged-state refusals follow correction, not blind retry/exit; preserve hard stops. Map unknown errors to closed codes (Feature 022: `exchange-context-lost`). Checkpoints/equal state grant no identity, takeover, or cleanup authority.
- Inspect upstream call paths before adapting; reuse existing code and notices. Add only requirements with current callers and testable outcomes (Feature 057: redundant Sharpie pixel machinery). Familiar UX patterns never replace approval.
- Judge accepted user journeys, not task counts; declare exclusions without assuming full CRUD or treating every correction as new scope. Feature 057 omitted draft editing; idea 058 tracks follow-up. This grants no scope or implementation authority.

Queue presence is not acceptance. Reverify versions; see Feature 057's log.

- Technical-docs extraction: separate immediate deliverables from optional acceptance; estimate files, units, calls, and time. Preserve approval above 20 units/calls or 10 minutes. Prefer bounded subtrees/fixtures; reuse verified evidence for deterministic metadata changes.
- Use `dude-learning-promotion` to distinguish solved lessons, existing guidance, proposals, and open defects across implementation, reviews, and delivery. Retain through the existing owner. A scoped retrospective is not exhaustive; synthesis adds no close hook, gate, or repeat retrospective.
- For two-phase requests, pre-submit failure is known-unsent; allow a new explicit request. After possible delivery, block replay unless authoritative evidence for that exact receipt proves nothing was sent.
