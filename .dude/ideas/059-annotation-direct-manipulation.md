## Core Problem And Verified Context

The Spec Lead read the current source for this refresh. Earlier reproduction and independent-review results remain attributed to the coordinator's supplied history; no new execution, reproduction, review, or test run is claimed. Paths below are under `src/extensions/dude/`.

- `frontend/review.jsx` loads `/review/engine.mjs` and mounts one `mountReview` owner for annotation state and history. Its existing comment-open message handling reveals Comments and focuses the selected annotation's comment field.
- In `ui/review/engine.mjs`, `add` already sets `state.selectedId = a.id` and retains the armed tool. The `select` action in `command` can select an older annotation without changing the tool; changing tools also retains selection.
- `render` draws the current visible selection independently of the tool. `ui/review/shapes.mjs` paints the dashed outline and 9x9 handles; `ui/review/geometry.mjs` supplies corner handles for box-like shapes and endpoint handles for Line/Arrow. Comment pins have no resize handles.
- `pointerDown` still gates both handle and marker hits on `state.tool === 'select'`. `markerAt` scans visible annotations topmost-first using `geometry.mjs`'s `hitTest`, which includes whole box/highlight faces and number badges. Reusing that whole-face test while drawing would intercept interior presses needed for overlapping drawings.
- `ui/review/styles.css` currently assigns only default-for-Select or crosshair-for-other-tools cursors. There is no hover-specific resize/move indication in the pointer handler.

**The core problem is a false affordance:** the UI draws working-looking grab handles that do nothing until the user switches to Select. Selection is retained, but the visible manipulation affordances are not actionable. This explains why the behavior feels broken rather than merely incomplete; it is not simply a failure to select the newly drawn shape.

Focused source reads also covered the geometry/number-hit tests in `src/extensions/dude/review.test.mjs`, real-engine pointer preview/cancellation coverage in `scripts/dude-canvas-ui/browser.test.mjs`, and production toolbar, caret, save, and sealed-PNG coverage in `scripts/dude-canvas-ui/t011-browser.test.mjs`. These are regression references, not fresh passing evidence.

## Known Issue: Out-And-Back Drag Opens Comments

The already-landed double-click-to-comment gesture has a known, independently reviewed, still-unfixed defect in `ui/review/engine.mjs`:

- The recognizer decides whether a press was a drag that cannot prime a comment-opening click using **final annotation equality**, `!same(state.annotations, current.before)`, rather than whether movement actually occurred.
- `pointerMove` rebuilds geometry from `drag.origin`, so dragging a shape out and back to its starting position restores exact equality.
- Drag a shape away and back, release, then single-click the same point within 500 ms: Comments opens on that **single click**.
- A qualifying second press that itself drags out and back opens Comments too.

The reviewer's required correction is behavioral: once a press actually moves or resizes an annotation, disqualify both its own double-press intent and its candidacy for the next press, even if the geometry later returns to origin. Final equality may remain the history-commit condition. No recognizer implementation is chosen during intake.

This was reviewed twice. The second round found this continuation, it was escalated to the user, and the user chose to defer it here. Keep it in this one idea because the direct-manipulation work will rework the same gesture recognizer; a separate record would scatter that work.

At first capture, everything else in that change was reported landed and green: box interiors and number badges are hit-testable, double-click-to-comment works from the Select tool, Enter parity works, and focus correctly lands in the **Comment (optional)** field. The current source still uses final equality for drag disqualification. Preserve the earlier evidence without treating the known defect as fixed.
