## Dude's Analysis

The answer above selects option 2. The findings below explain that choice; they are not additional user answers. Quota, verification, host, and documentation observations were supplied by the coordinator and were not rerun for this re-definition.

### Why the anonymous allowance runs out

Dude currently reads GitHub anonymously. The anonymous REST API allowance is 60 requests per hour per IP address, shared by everyone on that network. At 2026-10-20T18:20:38Z, the coordinator observed limit 60, remaining 0, and reset 2026-10-20T19:17:56Z through `GET https://api.github.com/rate_limit`, which consumes no quota.

The separate call-count fix reduces a catalog Reload from 26 to 6 GitHub API requests for the 20-pack E-G-C/dude catalog at `main`. It reads the packs tree recursively once, so the ordinary branch-ref Reload count stays six regardless of pack count within the existing acquisition bounds. The coordinator reports that the fix is implemented, independently verified by a Tester, and approved by a Code Reviewer, but is still uncommitted. It is not part of 089.

Even with that fix, 20 Reloads alone need 120 API requests, twice the anonymous hourly allowance. File bytes come from `raw.githubusercontent.com`, outside this REST API allowance.

### Whose login and quota apply

Dude's answer to the user's other-public-repository question: authenticated reads normally use the requesting user's 5,000-request hourly allowance, including reads of another person's public repository. The repository owner's quota is untouched, and the owner need not grant access to public content. The allowance is shared with the user's other tools using that login; authentication does not remove GitHub's limits.

### Chosen route: Dude's own sign-in

Use the familiar device-code sign-in pattern used by `gh auth login` and VS Code's GitHub sign-in: explain the benefit in Canvas, let the user start, and ask them to approve on github.com. Dude does not ask for or handle the GitHub password. The user registers an OAuth App owned by E-G-C once, with Device Flow enabled; Dude requests no scopes and needs only its public Client ID, not a client secret. The registration only names Dude on GitHub's authorization page and supplies that ID; Dude itself stays what it is, and nothing is installed on any account or repository.

Keep access only in session memory. The user accepted signing in each session; nothing in the answer requests credential storage. Signing out forgets local access but cannot revoke the GitHub authorization, so Canvas must point to GitHub's authorization settings.

OAuth apps can optionally issue expiring tokens; requesting `offline_access` opts a sign-in into them. Dude leaves the expiring-token option off and requests no scopes, so its tokens do not expire on a timer and it keeps no refresh token. A discarded token can remain valid at GitHub until revoked.

### Considered and declined: the app's token

Option 1 would request the app's `GH_TOKEN` through `joinSession({ requestedEnvironmentVariables: ['GH_TOKEN'] })`. The coordinator's 2026-10-29 observation, using a free `rate_limit` call, found a core limit of 15,000 and scopes `gist, project, read:org, repo, user, workflow, write:plugin_gateway_connections`. That token can write to accessible repositories, including workflows; it is broader than these public reads need.

The coordinator-reported SDK contract also puts the host's approval prompt before Canvas, offers no place for Dude's explanation, and rejects `joinSession()` if the user declines, preventing Dude from loading. The user's selection of option 2 declines this route. Do not request the app token or add a restart-based consent flow.

The larger observed app allowance does not justify its broader privileges. Dude's own sign-in normally gets the user's 5,000-request hourly allowance, shared with the user's other GitHub tools; it does not promise unlimited reads.

### Fallbacks

Retain today's anonymous reads whenever signed out. When GitHub refuses a read for rate limiting, Canvas explains the limit, suggests sign-in if signed out, and always points to the existing local-folder source option. A folder whose root contains `library/packs` can already be added under Settings > Packs > Sources > Add source and read in place without API calls.

A user-provided local folder may come from their own clone or another copy. Dude does not clone automatically. Local-folder reads and the existing handling of non-GitHub upstreams stay unchanged.
