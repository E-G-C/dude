# Idea: Terminal Work Manual Resolution

## Idea

Provide one explicit, user-authorized manual resolution path for a genuinely
terminal Work target, preserving its failure history and requiring fresh
independent acceptance. Keep it simple. Existing tasks keep their identities
and meaning, and independent verification and review remain mandatory. Do not
pretend that the old run resumed, succeeded, or settled its missing effects.

No automatic restart, restored supervisor, new tracker, or larger evidence
budget. Exclude a blanket override, registry, daemon, new lane or workflow
state, automatic cleanup or retry, and cross-session resume.

This deliberate core contract change must be defined and implemented before
use. Capture and definition authorize no bypass of current seals, cleanup or
closure of Feature 074, or other live resolution.

### Additional User-Directed Resolution Goal

The current user-directed goal is to implement the recommended resolution:
a minimal, separately authorized post-terminal administrative reconciliation
path for one named Lightweight task whose old autonomous Work run has no live
authority and whose later retained learning history deliberately prevents normal
fresh admission. This increment is proposed, not a completed capability.

Assess the current explicitly defined or amended obligations and a resolved
blocker without pretending they match the old failed attempt. Preserve durable
identity only with genuine exact current ownership and a recorded one-to-one
definition mapping. Do not rekey the task or reduce scope to manufacture success.

Require independent current acceptance and concrete owner-absence and
completion-effect evidence; unknown completion effects must refuse. Preserve
every old failure, learning projection and disposition, accounting entry, and
pending obligation unchanged. Distinguish any new same-task administrative close
from old Work success or settlement.

Prior independently authorized cleanup proves only resource disposition and
requires its actual preimages and results. Never restore an old supervisor, run
state, counters, pending attempt, permits, or effects from those records or
history.

Reuse the existing ordinary writer, owner log, snapshot, backlog, lint, and
selected-output projection. Add no command, schema, state store, tracker,
registry, daemon, generic override, or general recovery machinery. Do not
auto-start fresh Work, take over or resume another session, select the next task
automatically, expand budgets, or perform Git actions.

The separate definition must establish least-authority admission and permission
requirements, and the changed contract must be implemented before use. Current
user direction is not the old literal MANUAL confirmation or permission for
native operations. Capture grants no close.
